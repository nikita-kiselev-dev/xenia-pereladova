# Отчёт по motion-доработке

Дата: **24 октября 2026**. Основание: [WEBSITE_MOTION_PLAN.md](../../WEBSITE_MOTION_PLAN.md), [аудит](../research/motion-2026-10-24/AUDIT.md).
Статус: **версия для приёмки**. Не опубликована. Пользователь motion ещё не смотрел.

## Что реализовано

| Раздел плана | Реализация | Источник / калибровка |
|---|---|---|
| 3.1 Вход | Полный: grain → маскированные XP и «Ксения Переладова» → обложка `scale 1.5→1.001` → посимвольные подписи, барабаны 000–100 → обложка уменьшается до размера плитки → галерея раскрывается из стопки с `uAnim`. Повторный визит в сессии: только раскрытие из стопки и шапки. Есть «Пропустить». Честный статус загрузки отдельно от барабанов. Прямой URL Info/серии получает вход своего экрана | Тайминги из источника; удержание 2.4 s и предел ожидания 6 s — калибровка |
| 3.2 Grain | Своя `public/grain.png` 128 px на слое с overscan `10rem`, `2s steps(2)`, keyframes источника. Reduced motion — статичное зерно | Текстура сгенерирована `scripts/make-textures.py` по статистике образца |
| 3.2 Blur, курсор | Три слоя `backdrop-filter` 1/3/7 px с масками у шапки и подвала; курсор: lerp 0.075, нормализованный по dt, blur 3px, увеличивается над фото; скрыт на touch и reduced motion | P1 |
| 3.3 Hover фото | Displacement sampler `public/disp.jpg`, две UV-выборки `π/4` / `−3π/4`, коэффициент 0.4; `1.2s expo.out`, tween продолжается от текущего значения. Карточка выбирается `elementFromPoint` каждый кадр, поэтому при scroll под неподвижным курсором hover переходит. Focus даёт тот же акцент. Номер — барабаны, подпись — посимвольно после паузы 80 ms | Формула шейдера из источника |
| 3.4 Scroll | Свой ввод (GSAP Observer: wheel/trackpad/drag/touch, клавиши-стрелки), инерция с dt-нормализованным lerp, циклический перенос по стабильным плиткам без клонов. Desktop Overview — вертикальный цикл в свободной композиции, desktop List — горизонтальная лента, narrow Overview — лента с неподвижным XP. Изгиб — перспектива из z = `cos(x)·speed`, спроецированная вокруг центра экрана в ортокамере: в покое контур совпадает с DOM. Процент — фаза цикла; барабаны трогаются только при смене цифры | Геометрия композиции и коэффициенты изгиба — калибровка |
| 3.5 Переходы | Один постоянный renderer и одна DOM-галерея: Overview↔List и фильтры двигают те же фото (`1.4s power3.inOut`, размер `1s`), фаза каждого вида сохраняется. Gallery→Info: фото уходят в стороны, затем вход Info (fade, маска заголовка, блоки, портрет). Info→Gallery: выход Info, фото прилетают с боков. Новый маршрут прерывает текущий, интерфейс досинхронизируется | Тайминги Info из источника |
| 3.6 Тексты | Маска с rotate: XP, имя, «Обо мне», фильтры, «Вернёмся к фотографиям». Посимвольно: шапка, подвал, bio, метаданные серии, Info, подписи наведения. Scramble при наведении на ссылки и кнопки (`data-scramble`). Барабаны: номер наведения, проценты, номер mobile-серии, текущий кадр серии. Split один раз на элемент; ссылки/заголовки сохраняют `aria-label`, прочий текст — одну `sr-only` копию | SplitText и ScrambleText из уже установленного GSAP 3.15 |
| 3.7 Серия | Выбранная плитка встаёт в центр (`0.65s power4.inOut`, `uAnim` 0.3), растёт до рамки первого кадра (`1.2s`), остальные уходят. Обложка лежит под первым кадром, пока тот не декодирован, потом кадр проявляется поверх (не фиксированные 1.93 s). Close/Escape: страница гаснет, обложка возвращается с места кадра на своё место в галерее, focus возвращается на серию | P1 parallax и маска следующей серии — **не делались** |

## Технически проверено

- `npm run typecheck`, `npm test` (маршруты, manifest, новый `tests/gallery-layout.test.ts`: шов цикла и отсутствие пересечений на 1024–2560 и 390/768), `npm run build` — PASS. Предупреждение о chunk Three.js > 500 kB было и раньше.
- Сценарии `runCore` пройдены скриптом в браузере, без CUA harness: List, фильтр «портрет», открытие серии клавишей, Escape с возвратом фильтра и focus на `fashion`, Info, Back/Forward/Close, 4 категории, 5 быстрых переключений → один canvas, видимые тексты шапки.
- Fixture: no-WebGL (0 canvas, фото видны, серия/Close), reduced-motion stub, реальная потеря контекста (canvas удалён, все фото снова видимы, навигация работает).
- Реальная media query reduced motion через CDP (`v08`): нет canvas, intro, анимации зерна; focus возвращается.
- Исправлено в ходе проверки: смена маршрута во время входа оставляла скрытые тексты шапки; запятые фильтров не прятались маской; горизонтальный swipe на телефоне в Chrome запускал history back (`overscroll-behavior-x: none`).

## Motion-свидетельства

`node tests/motion-capture.mjs <baseURL> docs/qa/motion [сценарий…]` запускает локальный Chrome по CDP с реальными событиями мыши, колеса и touch и пишет screencast. Contact sheets и `capture.json` лежат в [motion/](motion/). MP4 (~70 MB, плохо сжимается из-за зерна) не коммитятся, их можно пересоздать. Сценарии: V01 cold/warm/skip, V03 hover, V04 scroll и phone swipe, V05 разделы, V06 серия, V08 reduced motion. Во всех `errors: []`, конечный маршрут верный.

Ограничения: headless Chrome рисует WebGL программно (SwiftShader, 10–30 fps), поэтому по клипам видны порядок и форма движения, а не плавность. В начале входа видна пауза около 1 s на загрузке Three.js и текстур. На реальном GPU её нужно измерить.

## Не проверено

- **Парное сравнение с оригиналом** (V01–V08 бок о бок при одном viewport): не записано. Тот же скрипт можно направить на оригинал, но сценарии завязаны на селекторы Xenia.
- **Производительность**: p95 frame time и long tasks на реальном GPU desktop и телефоне при DPR 2/3. Бюджет многослойного blur не измерен.
- **Real-device gate**: iPhone/Safari, Android/Chrome, orientation, background/foreground.
- **Hover-искажение крупным планом**: в клипе пик длится 1–2 кадра (`expo.out`), его видно, но для оценки силы на лицах нужен просмотр на реальном экране.
- 768×1024 и 320/1920 после изменений не переснимались. На 601–1023 px по ширине при альбомной высоте XP перекрывает ленту: так было и до доработки.
- Приёмка пользователем.

## Осознанные отличия от оригинала

- Перспектива — экранная проекция z в ортокамере, а не PerspectiveCamera: в покое кадр точно совпадает с DOM-плиткой, на скорости центр приближается, края уходят.
- В свободной композиции 4 ряда по шаблону якорей. Если выборка короче цикла (фильтры), она центрируется и не зацикливается.
- После серии обложка возвращается на своё место в галерее, а не сбрасывается к началу, как в источнике (так требует план).
